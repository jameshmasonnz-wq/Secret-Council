# Laptop host + mobile browser players

This project now supports a native Godot host using WebSocket and a Godot Web export for players' phones. Browsers cannot join an ENet room, so choose **WebSocket (website + mobile)** on the host and client.

## A. Export the website

1. Install the Godot 4.7 export templates from **Editor → Manage Export Templates**.
2. Open this project in Godot 4.7.
3. Open **Project → Export**, add a **Web** preset, and export to a folder such as `build/web/index.html`.
4. Publish the complete exported folder (not just `index.html`) to an HTTPS static host. The host must serve `.wasm` and `.pck` files with suitable MIME types. GitHub Pages or another static host can work.
5. Open the published website on a phone. The address field is in the lobby UI; enter the public WSS URL in section C.

The export is generated by the Godot editor. The project source archive does not contain generated `.wasm` or `.pck` files because export templates are installed per developer machine.

## B. Start the game server on the laptop

1. Open the same project in the desktop Godot editor (or run a native desktop export).
2. Leave **WebSocket (website + mobile)** selected.
3. Set the port to `24590` and click **Host room**.
4. Allow the app through the laptop firewall for incoming TCP on that port if prompted.

The WebSocket listener binds to all interfaces. The game host is authoritative and must remain running throughout the game.

## C. Make it reachable from phones over the internet

A phone on a different network cannot normally reach a laptop's private IP. You need a public endpoint that forwards secure WebSocket connections (`wss://`) to the laptop's local WebSocket listener.

One possible approach is a temporary Cloudflare Tunnel (install `cloudflared` first):

```sh
cloudflared tunnel --url http://localhost:24590
```

Use the HTTPS hostname printed by the tunnel as the public endpoint. In the mobile game's **Server URL / address** field, enter it as `wss://YOUR-HOSTNAME.trycloudflare.com` (replace with the actual hostname printed for your tunnel). Keep the tunnel running for the entire session. Quick Tunnel hostnames can change when restarted. Check the tunnel provider's current instructions and terms before relying on this for a real event.

This assumes the tunnel forwards WebSocket upgrade requests to the local WebSocket server on port `24590`. If your tunnel or reverse proxy is configured differently, update its origin/upgrade settings accordingly. Do not share the public endpoint widely; there is no authentication in this prototype.

For players on the same trusted Wi-Fi, you can test with a desktop browser or native desktop client using `ws://LAPTOP-LAN-IP:24590`. An HTTPS-hosted website requires `wss://`, so plain `ws://` will be blocked by the browser.

## D. Test checklist

- [ ] Host starts on laptop with WebSocket selected.
- [ ] Two desktop instances can connect over `ws://127.0.0.1:24590`.
- [ ] Exported site loads on a phone over HTTPS.
- [ ] Phone connects using the public `wss://` endpoint.
- [ ] Five or more players connect before starting.
- [ ] Private role info is visible only on each player's own device.
- [ ] Test disconnects, voting, policy selections, and special powers before using with a group.

## Known gaps

- Token-based reconnect and seat recovery are not complete.
- The UI may need a dedicated portrait/mobile layout pass.
- This is not hardened for hostile clients or public matchmaking. A host can inspect every role, and there is no account authentication or moderation system.
- This workflow has not been end-to-end tested in a real browser/tunnel environment from this build environment.


## Mobile portrait UI notes (v4)
- Lobby and gameplay switch to a stacked single-column layout when the viewport is 760 px wide or narrower.
- Both screens scroll vertically so controls remain reachable on short phone screens.
- Mobile/web action buttons have larger tap targets; Ja/Nein voting uses high-contrast green/red buttons.
- Rotate the phone or resize the browser to confirm the layout switches correctly. The source changes have not been rendered in a real Godot Web export in this environment.
